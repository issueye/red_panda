# Wave D-1: MCP Crash/Restart Budget — Implementation Plan

> **For implementers:** Add per-server crash budget to MCP Manager. Behavior change is contained: failing servers get auto-disabled after threshold; provider-visible tools hide immediately. Backward-compatible: env-off / threshold-0 → behaves exactly like today.

**Date:** 2026-07-20
**Goal:** 让 Agent Runtime 的 MCP 子系统在某个 MCP server 反复启动失败时自动禁用它（3 次 / 60 秒，可 env 覆盖），禁用后从 provider 工具列表中同步移除、`ExecuteTool` 拒调。这是 docs/19 §7.7 明文规定的设计，本次落地。
**Architecture:** Manager（Runtime 进程单例）持有 per-server 计数器；crash budget 状态跨 run 共享（per-Manager），按 `MCPServerConfig.Name` 分桶。失败识别限定为"启动阶失败"（spawn / open / initialize），业务 call 失败不计入。
**Parent docs:** [docs/19 §7.7](../19-mcp-stdio-tools-design.md)、[docs/plans/2026-07-19-convergence-wave.md](2026-07-19-convergence-wave.md) §5 Wave D

## 1. 背景与边界

探索代码后，约束已明确（来自 docs/19 §7.7 与代码现状）：

| 约束 | 来源 | 处理 |
|---|---|---|
| 阈值 3 次/60 秒，禁用到进程结束或 config 变更 | docs/19 §7.7 | 硬编码默认 + env 覆盖 |
| 状态跨 run 共享（per-Manager） | docs/19 §7.7 "Runtime process lifetime" | 放 Manager 字段，不放 bindings |
| per-server 标识 | MCPServerConfig 无 ID，仅有 Name | 用 Name 作 key（用户字符串） |
| 禁用后从 provider 工具列表移除 | docs/19 §7.4 | PrepareToolsForRun 跳过被禁用的 server |
| 失败已被映射为 tool_failed | docs/19 §11.4 | 无需新事件通道 |
| 错误是 plain fmt.Errorf，无类型化 | mcpkit/session.go | 用错误消息前缀识别启动阶失败 |

### 1.1 失败口径（已确认）

**只计启动阶失败**：spawn/open 失败、start timeout、initialize 失败。
**不计**：tools/call 业务失败（含 timeout、isError、stderr）。理由：业务 call 失败可能只是某个工具有 bug，server 本身是好的；只有 server 起不来/不响应 MCP 握手才代表"server 坏了"。

识别方法（基于 mcpkit/session.go:354-403）：错误消息前缀模式：
- `tools/call failed:` 前缀 → **业务阶，不计**
- 其它（包括 `initialize failed:`、`start timeout after Xms`、原始 spawn 错误）→ **启动阶，计 crash**

### 1.2 非目标

- 不引入 MCP 进程复用（Wave D 后续 backlog）
- 不做 cross-run discovery 缓存（Wave D 后续 backlog）
- 不做协议级 cancellation notification（Wave D 后续 backlog）
- 不做协议违规专门状态码（Wave D 后续 backlog）
- 不改 mcpkit 包的公开 API（只在 Manager 层加状态）

## 2. 实现切片

### Task D1-1: Manager 增加 crash budget 状态结构
**Files:**
- Create: `modules/agent/internal/mcp/budget.go`

**Steps:**
1. **Step 1**: 定义 per-server 失败追踪结构：
   ```go
   // serverFailure tracks startup-phase failures for one MCP server.
   // Locked by Manager.mu; lifetime is the Manager (Runtime process).
   type serverFailure struct {
       recent   []time.Time  // timestamps of startup-phase failures within the window
       disabled bool         // set true when threshold hit; stays until ResetFailureState
   }

   // isStartupPhaseFailure reports whether err came from spawn/open/initialize
   // (i.e., the server itself is broken), as opposed to a tools/call business error.
   func isStartupPhaseFailure(err error) bool {
       if err == nil { return false }
       msg := err.Error()
       // mcpkit.Call wraps initialize failures with "initialize failed:" and
       // returns spawn/start-timeout errors with no "tools/call failed:" prefix.
       // Business call failures are wrapped with "tools/call failed:".
       return !strings.HasPrefix(msg, "tools/call failed:")
   }
   ```
2. **Step 2**: 定义阈值常量 + env 读取：
   ```go
   const (
       defaultCrashLimit   = 3
       defaultCrashWindow  = 60 * time.Second
   )

   func crashLimitFromEnv() int {
       if v := strings.TrimSpace(os.Getenv("RED_PANDA_MCP_CRASH_LIMIT")); v != "" {
           if n, err := strconv.Atoi(v); err == nil && n >= 0 { return n }
       }
       return defaultCrashLimit
   }

   func crashWindowFromEnv() time.Duration {
       if v := strings.TrimSpace(os.Getenv("RED_PANDA_MCP_CRASH_WINDOW_MS")); v != "" {
           if n, err := strconv.Atoi(v); err == nil && n > 0 {
               return time.Duration(n) * time.Millisecond
           }
       }
       return defaultCrashWindow
   }
   ```
   说明：limit=0 时整个 budget 功能关闭（每次失败都不计数、不禁用），这是逃生舱。
3. **Step 3**: 写包级 helper `failureDecision(recent []time.Time, now time.Time, window time.Duration, limit int) (newRecent []time.Time, disable bool)` 纯函数，便于单测：
   - 过滤掉 `now - window` 之前的旧记录
   - 加入本次（如果 limit==0 直接返回 nil,false）
   - 若过滤后 ≥ limit → 返回 (newRecent, true)

**Verify:** `go test ./modules/agent/internal/mcp/... -count=1 -run TestFailureDecision`

### Task D1-2: Manager 集成 budget 字段与方法
**Files:**
- Modify: `modules/agent/internal/mcp/manager.go`
- Modify: `modules/agent/internal/mcp/tools.go`
- Modify: `modules/agent/internal/runtime/mcp_bridge.go`

**Steps:**
1. **Step 1**: Manager struct 增加 budget 状态：
   ```go
   type Manager struct {
       version  string
       log      io.Writer
       tracker  *mcpkit.Tracker
       mu       sync.Mutex
       bindings map[string]map[string]ToolBinding
       // failures tracks startup-phase failures per server Name (docs/19 §7.7).
       // Lifetime is the Manager (= Runtime process). Reset only by config change
       // (currently no Reset API; the process must be restarted).
       failures   map[string]*serverFailure
       crashLimit  int
       crashWindow time.Duration
   }
   ```
   `NewManager` 中初始化：`failures: map[string]*serverFailure{}, crashLimit: crashLimitFromEnv(), crashWindow: crashWindowFromEnv()`。
2. **Step 2**: Manager 加 3 个内部方法（不导出）：
   ```go
   // isDisabled reports whether serverName has been auto-disabled by the budget.
   func (m *Manager) isDisabled(serverName string) bool {
       m.mu.Lock(); defer m.mu.Unlock()
       f, ok := m.failures[serverName]; return ok && f.disabled
   }

   // recordStartupFailure records a startup-phase failure for serverName and returns
   // whether the budget has now disabled the server. Caller must have already
   // classified the error as startup-phase via isStartupPhaseFailure.
   func (m *Manager) recordStartupFailure(serverName string, err error) bool {
       if m.crashLimit <= 0 { return false }  // budget disabled
       m.mu.Lock(); defer m.mu.Unlock()
       f := m.failures[serverName]
       if f == nil { f = &serverFailure{}; m.failures[serverName] = f }
       if f.disabled { return true }  // already disabled, no-op
       now := time.Now()
       f.recent, f.disabled = failureDecision(f.recent, now, m.crashWindow, m.crashLimit)
       return f.disabled
   }

   // DisabledServers returns the sorted list of currently-disabled server Names.
   // Used by PrepareToolsForRun to skip dead servers before any discovery attempt.
   func (m *Manager) DisabledServers() []string {
       m.mu.Lock(); defer m.mu.Unlock()
       out := make([]string, 0, len(m.failures))
       for name, f := range m.failures {
           if f.disabled { out = append(out, name) }
       }
       sort.Strings(out)
       return out
   }
   ```
3. **Step 3**: `PrepareToolsForRun` 在 server 循环里加禁用检查：
   ```go
   for _, server := range servers {
       if !server.Enabled { continue }
       if strings.TrimSpace(server.Command) == "" || strings.TrimSpace(server.Name) == "" {
           continue
       }
       if m.isDisabled(server.Name) {
           fmt.Fprintf(m.log, "mcp skip %s: disabled by crash budget\n", server.Name)
           continue
       }
       discovery := m.DiscoverServer(ctx, workspace, server)
       if discovery.Status != "ready" {
           fmt.Fprintf(m.log, "mcp discover %s: %s (%s)\n", ...)
           // Record startup-phase failure if applicable.
           if isStartupPhaseFailure(errors.New(discovery.Error)) {
               if m.recordStartupFailure(server.Name, errors.New(discovery.Error)) {
                   fmt.Fprintf(m.log, "mcp %s: disabled by crash budget\n", server.Name)
               }
           }
           continue
       }
       // ... existing binding logic
   }
   ```
   注意：`DiscoverServer` 返回的 `discovery.Error` 是 mcpkit 包装过的错误消息，前缀规则与 mcpkit.Call 一致（discovery 用同一 session 生命周期）。
4. **Step 4**: `ExecuteTool` 在 binding 取到后、`CallTool` 之前加禁用检查：
   ```go
   func (m *Manager) ExecuteTool(ctx, runID, workingDir, call) (string, error) {
       binding, ok := m.Binding(runID, call.Name)
       if !ok {
           return "", fmt.Errorf("unknown MCP tool %s", call.Name)
       }
       if m.isDisabled(binding.Config.Name) {
           return "", fmt.Errorf("MCP server %s disabled by crash budget (too many startup failures)", binding.Config.Name)
       }
       output, err := m.CallTool(ctx, workingDir, binding.Config, binding.RawName, call.Arguments)
       if err != nil && isStartupPhaseFailure(err) {
           if m.recordStartupFailure(binding.Config.Name, err) {
               fmt.Fprintf(m.log, "mcp %s: disabled by crash budget after ExecuteTool failure\n", binding.Config.Name)
           }
       }
       return output, err
   }
   ```
   注意：binding 在 run 启动时已经注册；server 在 run 中途被禁用时，binding 仍然在但 ExecuteTool 拒调。provider 看到的工具列表要等到下一个 run 的 PrepareToolsForRun 才会同步更新（见下"限制"）。
5. **Step 5**: `mcp_bridge.go` 的 `toolsForReply` 加 DisabledServers 日志（可选，但便于诊断）：
   ```go
   if disabled := r.mcp.DisabledServers(); len(disabled) > 0 {
       fmt.Fprintf(r.log, "mcp disabled servers: %s\n", strings.Join(disabled, ", "))
   }
   ```

### Task D1-3: 扩展 fake MCP server 支持"前 N 次失败"
**Files:**
- Modify: `modules/agent/internal/runtime/mcp_discovery_test.go`（helper 进程）

**Steps:**
1. **Step 1**: 在 `TestMCPHelperProcess` 的 mode 分支里加 `fail-startup-until-N`：进程启动时读 `RED_PANDA_MCP_FAIL_UNTIL` env（格式 `<文件路径>,<N>`），文件维护一个计数器；< N 时立即 `os.Exit(1)`（模拟 spawn 即崩）；>= N 时走正常 ready 模式。
   ```go
   case "fail-startup-until-N":
       path, n := parseFailUntilEnv()  // helper
       count := atomicIncrementFile(path)  // read-modify-write
       if count <= n {
           os.Exit(1)  // simulate spawn-time crash
       }
       // fall through to "ready" handling
   ```

3. **Step 3**: 复用现有 `helperMCPConfig` 框架添加 `WithFailStartupUntilN(n int)` 选项，生成对应 env + 文件路径。

## 4. 完成定义

- Manager 持有 per-server crash budget 状态（per-Manager，跨 run）
- `PrepareToolsForRun` 跳过被禁用的 server（provider 视图中工具消失）
- `ExecuteTool` 对被禁用 server 返回明确错误
- 启动阶失败（spawn/open/initialize）计数，业务阶失败（tools/call）不计数
- env `RED_PANDA_MCP_CRASH_LIMIT=0` 可关闭整个功能（逃生舱）
- docs/19 §7.7 状态从 "Not yet implemented" 升级为 "Implemented"
- 所有现有 MCP 测试零修改通过

## 5. 已知限制（不在本次范围）

- **Run 中途禁用 → provider 工具列表 stale**：binding 在 run 启动时注册，server 在 run 中途被禁用时，binding 仍在；provider 该 turn 看到的工具列表不会立即收缩，但 `ExecuteTool` 会拒调。下一个 run 的 `PrepareToolsForRun` 才会真正跳过该 server。这与 docs/19 §7.7 "Restart lazily on the next discovery or call" 一致。
- **状态持久到 Runtime 进程结束**：没有 `Reset` API。如果用户在 Gateway 改了 MCP server 配置（同名覆盖），目前 Runtime 不会重置该 server 的 budget（因为 Runtime 不知道 config 变了）。这是 docs/19 §7.7 "until config changes" 的半实现——真正实现需要 Runtime 监听 config 变更事件，留到 Wave D 后续或独立 wave。
- **不区分失败类型**：所有启动阶失败一视同仁。未来如果发现"timeout 与 spawn-fail 应分别计不同权重"，再细分。
