# red_panda 桌面端 UED 规范

## 1. 文档信息

- 规范版本：1.0
- 建立日期：2026-07-10
- 适用范围：Wails v3 桌面端及后续复用同一网关协议的 Web 客户端
- 设计基线：React + JavaScript + shadcn/ui 风格基础组件 + lucide-react
- 产品形态：面向本地 AI Agent 任务的高密度工作台
- 品牌资产：沿用 `red-panda-mark.svg`，不得重绘或替换为通用图标

本文是桌面端设计、实现、评审和验收的共同基线。出现实现差异时，应先更新规范或形成明确的例外记录，不能依赖组件内的隐含约定。

## 2. 用户与核心任务

主要用户是需要在本地工作区中持续执行、观察和控制 AI Agent 的开发者及高级用户。界面首先服务以下任务：

1. 创建、切换、分支和压缩会话。
2. 输入任务并持续阅读主代理输出。
3. 观察工具调用、子代理、授权请求和运行状态。
4. 在风险信息充分的前提下批准或拒绝工具操作。
5. 查看工作区文件、运行记录和记忆。
6. 配置模型服务、运行模式、权限策略和子代理后端。

## 3. 设计原则

### 3.1 工作优先

- 首屏直接进入可工作的会话界面，不增加营销页或功能说明页。
- 中央对话区始终是主要视觉区域；状态、检查器和设置不得抢占任务输入与输出。
- 高频命令一步可达，低频配置进入设置面板。

### 3.2 信息可追溯

- 主代理、子代理、工具和授权事件必须按网关 `root_seq` 的真实顺序组成统一时间线。
- 技术序号用于诊断，不得成为普通用户的主要阅读信息。
- 同一事件在对话区和检查器中的状态、名称和时间必须一致。

### 3.3 风险优先

- 授权请求必须先说明“什么工具、什么风险、对什么对象、使用什么参数”，再提供决策按钮。
- 危险操作不能只依赖颜色表达。
- 删除配置、覆盖文件等不可逆操作必须二次确认或提供可撤销机制。

### 3.4 安静且高密度

- 使用浅色表面、克制边框、小范围品牌橙和语义状态色。
- 页面区块不使用悬浮卡片造型；卡片仅用于消息、工具、授权、子代理和重复条目。
- 动效只用于说明状态变化，持续时间控制在 120-200ms。

## 4. 信息架构

```text
App Shell
├─ TopBar：品牌、连接状态、重连、设置
├─ Workspace
│  ├─ Sidebar：工作区、会话和会话命令
│  ├─ ChatPanel：统一事件时间线和输入器
│  └─ Inspector：工作区、子代理、活动、记忆
├─ Settings：模型服务、运行、权限、子代理
└─ StatusBar：连接、运行和事件同步摘要
```

职责边界：

- 对话区回答“现在发生了什么、下一步需要什么”。
- 右侧检查器回答“细节是什么、历史是什么”。
- 状态栏只展示全局健康摘要，不承载主要操作。
- 设置面板只承载低频配置，不混入当前运行的即时控制。

## 5. 窗口与响应式布局

Wails 默认窗口为 `1280 x 820`，最小窗口为 `980 x 640`。桌面端必须在最小窗口内保持全部核心能力可达。

| 视口 | 布局规则 |
| --- | --- |
| `>= 1101px` | 252px 左栏 + 弹性对话区 + 320px 检查器 |
| `980-1100px` | 220px 左栏 + 弹性对话区；检查器改为 360px 右抽屉 |
| `761-979px` | Web 扩展模式；会话导航与检查器均使用抽屉，对话区独占内容宽度 |
| `<= 760px` | 单栏模式；顶栏命令压缩为图标或菜单，所有抽屉不得遮住输入器 |
| `<= 520px` | 设置面板占满可用宽度，不保留无意义的背景边带 |

固定尺寸：

- TopBar：58px。
- StatusBar：28px。
- 常规控件：最小高度 32px。
- 主要触控目标：窄屏下至少 40 x 40px。
- 设置抽屉：桌面 380px，最大 420px；窄屏为 `100vw`。

布局约束：

1. 浮动工具栏必须占用保留空间，不能覆盖消息、状态或输入内容。
2. 每个滚动区域只有一个明确的滚动所有者。
3. 页面不得出现水平滚动条。
4. 隐藏的抽屉必须从视觉树、焦点顺序和辅助技术树中同时移除。
5. 从桌面切换到窄窗时，当前会话、草稿、检查器页签和滚动位置应保留。

## 6. 视觉基础

### 6.1 色彩

| 角色 | 建议值 | 使用规则 |
| --- | --- | --- |
| 页面背景 | `#f7f8fb` | 应用底色 |
| 主表面 | `#ffffff` | 对话区、顶栏、抽屉 |
| 次表面 | `#f2f4f7` | 侧栏、弱分区 |
| 主文本 | `#18212f` | 正文、关键数据 |
| 次文本 | `#667085` | 元数据、辅助说明，白底对比度 4.97:1 |
| 品牌色 | `#d95f24` | LOGO 呼应、非文字强调，不直接承载白色小字 |
| 主按钮 | `#c45119` | 白字对比度 4.63:1 |
| 主按钮悬停 | `#b9380b` | 白字对比度 5.78:1 |
| 成功文本 | `#067647` | 与成功背景组合 |
| 警告文本 | `#b54708` | 与警告背景组合 |
| 危险文本 | `#b42318` | 与危险背景组合 |
| 信息文本 | `#3538cd` | 运行中、同步中 |

`#98a2b3` 仅可用于非关键装饰或禁用态，不得用于 10-12px 的必要信息。正文和控件文字对比度至少 4.5:1，图标及边界等非文字信息至少 3:1。

### 6.2 字体

- 界面字体：`Inter, "Segoe UI", system-ui, sans-serif`。
- 代码字体：`"Cascadia Code", Consolas, monospace`。
- 页面/面板标题：14px，600-700。
- 条目标题和正文：13px，正文行高至少 1.5。
- 标签和元数据：12px；必要信息不得低于 11px。
- 代码和序号：11px；10px 仅限非关键紧凑徽标。
- 字号不随视口宽度缩放，字距保持 0。

### 6.3 间距、圆角与阴影

- 间距使用 `4 / 6 / 8 / 10 / 12 / 14 / 18 / 24px`。
- 控件与卡片圆角 8px，紧凑条目和代码块 6px，状态徽标可使用胶囊圆角。
- 普通区块依赖边框分层；阴影仅用于菜单、抽屉和模态层。
- 同级内容间距保持一致，禁止通过随机 margin 修补布局。

## 7. 组件规范

### 7.1 TopBar

- 左侧固定显示 LOGO 与 `red_panda`。
- 右侧依次为连接状态、重连、设置。
- 连接地址放在 tooltip 或连接详情中，不在顶栏持续占位。
- 重连中必须禁用重复操作并显示进行中状态。
- 窄屏优先保留品牌、状态和设置，其余命令进入菜单。

### 7.2 Sidebar

- “新建会话”是主命令；分支、压缩是当前会话的次命令。
- 会话条目至少展示标题和可区分的运行状态；长标题单行截断并提供完整 tooltip。
- 当前会话同时使用背景、边框或标记表达，不只依赖颜色。
- 窄屏隐藏 Sidebar 时必须提供等价的会话导航入口。

### 7.3 Chat 时间线

- 消息、工具、授权和子代理摘要使用单一数据模型，按 `root_seq` 稳定排序。
- 同一流内按 `stream_id + stream.seq` 合并增量，避免重复和跳序。
- 默认跟随最新输出；用户向上滚动后暂停跟随并显示“回到最新”按钮。
- 新内容到达时不能强制抢走键盘焦点。
- 支持 Markdown、代码块、复制代码和长行换行；外部链接需明确提示。
- 主代理与子代理使用文字标签和图标区分，不能只使用颜色。
- 普通视图显示“主代理 / 子代理 / 工具 / 授权”；协议字段进入诊断详情。

### 7.4 Composer

- 输入框始终靠近窗口底部，运行输出不能将其挤出可视区。
- 空内容不能发送；发送中防止重复提交。
- `Ctrl+Enter` / `Cmd+Enter` 发送，`Enter` 换行。
- 运行中主按钮替换为取消按钮，取消后提供明确状态反馈。
- 草稿按会话保存，切换会话后可恢复。

### 7.5 ToolCallCard

- 必须显示展示名、原始工具名、风险、状态、参数和输出/错误。
- 参数和长输出默认可折叠；流式输出区域保持稳定高度并允许复制。
- “运行中、完成、失败、拒绝”同时使用图标、文字和语义色。
- 连续工具调用可折叠为组，但不能破坏真实事件顺序。

### 7.6 PermissionCard

- 必须显示：工具名、风险等级、摘要、目标对象、参数预览、所属代理。
- 默认操作为“拒绝”和“允许一次”，危险操作的拒绝按钮优先获得初始焦点。
- 高风险授权使用模态确认，普通授权可内联处理。
- 决策提交期间禁用两个按钮；成功后保留决策结果，失败后允许重试。

### 7.7 Inspector

- 页签固定为“工作区、子代理、活动、记忆”，支持方向键、Home 和 End。
- 桌面常驻，紧凑窗口改为右抽屉。
- 抽屉打开后焦点进入面板，`Escape` 关闭，关闭后焦点返回触发页签。
- 关闭状态使用 `hidden`、`inert` 或等价机制，不能保留屏外可聚焦元素。
- 子代理详情至少包含任务、父运行、状态、最近输出、工具和错误。

### 7.8 Settings

- 分为“模型服务、运行与代理、工具与授权”三个可扫描分组或页签。
- API 密钥使用密码输入，不回显完整值。
- 删除模型配置必须确认；保存、删除和刷新均显示进行中及错误状态。
- 模态打开后焦点进入标题或关闭按钮，焦点限制在面板内，`Escape` 关闭并返回触发按钮。
- 小于等于 520px 时全宽显示，标题和底部操作固定，内容区独立滚动。

### 7.9 Status、Toast 与空状态

- 状态必须通过统一映射生成，禁止组件自行创造同义词。
- 异步错误使用可关闭通知，严重错误使用 `role="alert"`。
- 连接和运行状态变化使用 `aria-live="polite"`，但流式 token 不逐字播报。
- 空状态说明当前状态和可执行的下一步，不显示协议名或内部术语。

## 8. 交互与反馈

| 场景 | 必需反馈 |
| --- | --- |
| 建立连接 | 状态从“连接中”变为“已连接”或“连接失败” |
| 重连 | 按钮忙碌态、禁止重复点击、失败可重试 |
| 发送任务 | 立即插入用户消息，输入器进入运行态 |
| 流式输出 | 稳定追加，不闪烁、不改变既有条目尺寸 |
| 取消运行 | 显示“正在取消”，最终落为“已取消”或失败 |
| 授权决策 | 按钮忙碌态，结果原位保留 |
| 保存设置 | 成功提示或明确错误，不静默失败 |
| 断线恢复 | 保留已有内容，恢复后按游标补齐事件 |

所有点击操作应在 100ms 内产生视觉响应。加载超过 400ms 时显示进行中状态，超过 10 秒时提供可理解的等待说明或取消入口。

## 9. 文案规则

- 主界面使用用户语言：连接、运行、事件、主代理、子代理、工具、授权。
- `WebSocket`、`JSON-RPC`、`root_seq`、`agent_seq`、`stream_id` 只出现在诊断详情或开发模式。
- 按钮使用动词，如“发送、取消、允许、拒绝、保存、关闭”。
- 错误信息包含发生对象和下一步，避免只显示原始异常。
- 中英文混排时，协议值和代码使用等宽字体，产品文案保持中文一致性。

## 10. 无障碍要求

最低目标为 WCAG 2.2 AA：

1. 所有功能可仅用键盘完成。
2. 焦点指示清晰，且不会进入不可见区域。
3. 图标按钮必须有可访问名称和 tooltip。
4. 页签、对话框、列表框使用完整语义和关联关系。
5. 颜色不是状态或风险的唯一表达方式。
6. 正文对比度至少 4.5:1，大文本及非文字图形至少 3:1。
7. 支持 `prefers-reduced-motion: reduce`，减少抽屉和加载动效。
8. 200% 缩放下不丢失核心功能，不出现双向滚动。

## 11. 验收清单

每个桌面端功能在合并前至少完成：

- `1280 x 820`、`980 x 640` 两个 Wails 窗口检查。
- `760 x 760`、`390 x 760` 两个 Web 扩展视口检查。
- 无水平溢出、无内容遮挡、无不可达操作。
- Tab 顺序、页签方向键、Escape、焦点返回测试。
- 主代理与子代理并发事件顺序测试。
- 断线恢复、授权等待、工具失败、空会话和长输出测试。
- 文本与控件对比度检查。
- 单元测试、前端构建和 Playwright UI 测试通过。

## 12. 规范维护

- 新组件优先扩展现有 UI primitives，不在业务组件中复制控件样式。
- 新状态、新颜色和新断点必须先进入本文或设计 token。
- 规范变更需同步更新 Playwright 验收用例。
- 例外必须记录原因、影响范围和清理版本，不能长期依赖临时 CSS。
