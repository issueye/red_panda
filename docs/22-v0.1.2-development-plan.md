# v0.1.2 Development Plan

Updated: 2026-07-09

v0.1.2 is the first MCP implementation slice after the v0.1.1 stabilization/design release.

Scope is intentionally narrow: implement MCP server configuration contracts and Gateway CRUD only. Runtime MCP stdio process execution remains blocked until this slice is complete and verified.

## 1. Baseline

Expected baseline:

- v0.1.1 stabilization/design work is complete.
- MCP stdio tools design exists in `docs/19-mcp-stdio-tools-design.md`.
- Desktop UI normalization exists in `docs/21-ui-normalization.md`.
- MCP stdio tools are still not implemented.

## 2. Goal

v0.1.2 should deliver MCP-1:

1. Protocol DTOs for MCP server configuration.
2. Gateway persistence for MCP server configs.
3. Gateway HTTP CRUD APIs for MCP server configs.
4. Validation for server name, command, args, cwd, env, timeouts, allowlists, and risk overrides.
5. Tests proving config persistence, redaction rules, validation, and API shape.
6. Protocol compatibility coverage for config CRUD.

## 3. Non-Goals

Do not include these in v0.1.2:

- Starting MCP stdio server processes.
- MCP `initialize`.
- MCP `tools/list`.
- MCP `tools/call`.
- Runtime tool registry changes.
- Permission evaluation for MCP tools.
- Desktop MCP settings UI.
- HTTP MCP transport.
- Plugin marketplace.

## 4. Deliverables

| Order | Deliverable | Scope | Done when |
| --- | --- | --- | --- |
| 1 | Protocol config DTOs | `modules/protocol` | MCP config structs serialize with stable JSON names and validation-friendly field shapes. |
| 2 | Gateway persistence | `modules/gateway/internal/gateway/model`, repository, migration | MCP server config records persist and load without executing commands. |
| 3 | Gateway service validation | `modules/gateway/internal/gateway/service` | Invalid names, commands, risk overrides, and timeout values are rejected. |
| 4 | Gateway HTTP CRUD | `modules/gateway/internal/gateway/controller`, routes | Create/list/get/update/delete APIs work and return redacted config data. |
| 5 | Tests | Gateway/service/controller/protocol tests | CRUD and validation are covered with deterministic tests. |
| 6 | Protocol compatibility | `scripts/protocol-compat.ps1` | External API smoke covers MCP config CRUD without starting MCP servers. |
| 7 | Docs/status sync | `docs/10-development-status.md`, `docs/11-structured-development-roadmap.md`, `docs/12-current-execution-plan.md`, `README.md` | Docs state v0.1.2 is MCP config CRUD only. |

## 5. Proposed API Shape

Base route:

```text
GET    /api/v1/mcp/servers
POST   /api/v1/mcp/servers
GET    /api/v1/mcp/servers/:id
PUT    /api/v1/mcp/servers/:id
DELETE /api/v1/mcp/servers/:id
```

Response shape should match the protocol DTO names from `docs/19-mcp-stdio-tools-design.md`:

```json
{
  "id": "mcp_srv_...",
  "name": "filesystem",
  "command": "mcp-filesystem",
  "args": ["--root", "."],
  "env": {},
  "cwd": "",
  "enabled": true,
  "timeouts": {
    "start_ms": 10000,
    "initialize_ms": 10000,
    "list_ms": 10000,
    "call_ms": 30000,
    "shutdown_ms": 3000
  },
  "tool_allowlist": ["read_file", "list"],
  "risk_overrides": {
    "read_file": "low"
  },
  "created_at": "2026-07-09T00:00:00Z",
  "updated_at": "2026-07-09T00:00:00Z"
}
```

Environment values may be stored in v0.1.2, but responses must be prepared for redaction. If secret redaction cannot be completed safely in this slice, env values should be limited to non-secret test-safe values and the limitation must be documented before release.

## 6. Validation Rules

Minimum validation:

- `name` is required, unique, lowercase ASCII, and must not contain whitespace, `__`, path separators, or shell metacharacters.
- `command` is required and must be a single executable string, not a shell command line.
- `args` must be an array of strings.
- `env` keys must be non-empty strings.
- `cwd` must be empty or a string; execution-time path checks are deferred.
- `timeouts` must be positive when provided and should normalize to defaults when omitted.
- `tool_allowlist` entries must be non-empty raw MCP tool names.
- `risk_overrides` values must be `low`, `medium`, or `high`.

Gateway must not execute `command` during validation.

## 8. Stop Rules

Pause if a change would:

- Start an MCP process.
- Parse MCP stdout.
- Add MCP tools to Runtime provider-facing tools.
- Add Desktop MCP UI before backend config CRUD is stable.
- Store or return unredacted secrets without an explicit redaction policy.
- Use shell interpolation for command validation.
- Bypass Gateway service validation.

## 9. Exit Criteria

v0.1.2 is done when:

1. Protocol DTOs exist and are tested.
2. Gateway CRUD persists MCP server configs.
3. Gateway service validation rejects unsafe or malformed config.
4. External protocol compatibility covers config CRUD.
5. Docs and release notes clearly say Runtime MCP process execution is not implemented.
6. Verification gates pass.
