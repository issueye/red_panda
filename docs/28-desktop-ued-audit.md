# red_panda 桌面端 UED 审计报告

## 1. 审计结论

审计日期：2026-07-10。

当前桌面端已经形成稳定的高密度工作台框架，品牌、三栏信息架构、基础组件、状态色和设置焦点管理方向正确。现状可支撑内部 v0.1 阶段使用，但尚未满足 `27-desktop-ued-specification.md` 的完整验收条件。

原始审计的主要阻断项集中在统一事件时间线、流式阅读、授权决策信息、最小窗口遮挡、隐藏抽屉焦点和颜色对比度。本轮优化已解决其中五项，授权卡的信息完整性已补齐，高风险授权独立模态仍作为后续增强项。第 4、5 节保留原始发现，用于追踪问题来源。

## 2. 审计范围与方法

审计基线：

- Git 基线：`53ed905`
- 包含当前工作区尚未提交的响应式与无障碍改进

5. 运行前端单元测试、构建和 UI 自动化测试作为回归基线。

## 4. P1 问题

P1 表示影响核心任务、错误决策或最小支持窗口，进入下一版本前应处理。

### UED-001 对话区没有统一事件时间线

- 证据：`ChatConversation.jsx` 先渲染全部消息，再渲染全部工具，最后渲染全部授权。
- 影响：主代理与子代理并发、工具调用和授权请求会失去真实发生顺序；用户无法准确理解 Agent 当前步骤。
- 建议：建立统一 timeline item 模型，以 `root_seq` 为全局顺序，以 `stream_id + stream.seq` 合并流式内容，再由单一列表渲染 message/tool/permission/subagent summary。

### UED-002 流式对话缺少跟随最新输出机制

- 证据：`ChatConversation.jsx` 没有滚动容器引用、增量跟随或“回到最新”控制。
- 影响：长任务继续追加输出时，用户可能停留在旧位置而看不到最新状态和授权请求。
- 建议：默认跟随底部；用户主动向上滚动后暂停跟随；新内容到达时显示“回到最新”按钮；授权请求到达时提供醒目但不抢焦点的提示。

### UED-003 授权卡缺少决策所需信息

- 证据：`PermissionCard.jsx` 仅展示摘要和详情，未稳定展示工具名、风险等级、参数预览、目标对象和所属代理。
- 影响：用户可能在信息不足的情况下批准文件、Shell 或其他高风险工具。
- 建议：补齐规范要求的六类信息；高风险授权使用确认对话框；提交决策期间禁用操作并显示结果或重试。

### UED-004 Wails 最小窗口下辅助栏遮挡消息

- 证据：在 `980 x 820` 实测，辅助栏区域为 `x=722..968, y=70..110`，首条消息为 `x=282..956, y=82..151.6`，两者发生重叠。
- 原因：`app.css` 在 `<=1100px` 将 `.right-panel-rail` 放在对话区上方，但只在 `<=760px` 给 `.conversation` 增加顶部空间。
- 影响：当前 Wails 声明的最小宽度 980px 已触发问题，消息元数据和文本可能被覆盖。
- 建议：为 980-1100px 布局增加独立检查器工具栏行，或将入口收进顶栏；不要用悬浮层覆盖对话内容。

### UED-005 关闭的右侧抽屉仍可被键盘和读屏访问

- 证据：在 980px 宽度下，`.right-panel` 被平移到屏外，但没有 `hidden`、`inert` 或 `aria-hidden`；其中活动页签仍为 `tabIndex=0`。
- 影响：键盘焦点可进入不可见面板，读屏会读到两套“辅助面板”页签，造成焦点丢失和重复导航。
- 建议：抽屉关闭时设置 `inert` 和 `aria-hidden=true`，或条件渲染面板；打开时移动焦点，关闭时返回触发页签。

### UED-006 主按钮文字对比度不足

- 证据：白字 `#ffffff` 与当前品牌背景 `#d95f24` 的对比度为 3.74:1，低于普通文字 4.5:1 的 AA 要求。
- 影响：发送、允许等关键按钮的小字号文字在低对比度屏幕上可读性不足。
- 建议：品牌识别色保留为 `#d95f24`，主操作背景改为 `#c45119` 或更深，悬停使用 `#b9380b`。

## 5. P2 问题

P2 表示不阻断当前内部使用，但会降低效率、一致性或后续 Web 复用质量。

| ID | 问题 | 影响与建议 |
| --- | --- | --- |
| UED-007 | 设置面板信息过长且缺少分组导航 | 将模型服务、运行与代理、工具与授权拆成页签或明确分组，降低扫描成本 |
| UED-008 | 520px 设置面板仍只有 420px | 实测左右各留 50px；覆盖 `max-width`，在 `<=520px` 使用真正全宽 |
| UED-009 | 760px 以下直接隐藏会话栏 | 外部 Web 窄屏会失去会话切换、分支和压缩入口；增加会话抽屉或菜单 |
| UED-010 | 活动面板仍显示 `seq`、`root#` | 默认改为“事件 004、主代理”，原始协议值放入诊断详情 |
| UED-011 | 子代理只有列表，没有详情和输出 | 增加任务、父运行、最近输出、工具、错误和完整 transcript |
| UED-012 | 对话消息不支持 Markdown 和代码块 | 当前使用普通 `<p>`；增加安全 Markdown、代码复制和长行处理 |
| UED-013 | 动态状态没有 live region | 连接、运行和错误状态变化对读屏不可感知；状态栏用 polite，错误用 alert |
| UED-014 | 缺少 reduced-motion 规则 | 对 `prefers-reduced-motion` 关闭抽屉过渡和持续动画 |
| UED-015 | 模型配置删除没有确认 | 删除按钮直接调用接口；增加确认或可撤销反馈 |
| UED-016 | `--color-text-soft` 对比度仅 2.58:1 | 限制为装饰/禁用态，必要元数据统一使用 `--color-text-muted` |

## 6. 现有改进的评价

当前未提交的 UI 改动解决了上一轮评审中的多项问题：

- 去除了 760px 以下的强制页面最小宽度，窄窗不再产生水平滚动。
- 在紧凑窗口增加了右侧检查器入口和抽屉。
- 设置对话框已补齐焦点进入、焦点限制、Escape 和焦点返回。
- 页签已增加 ARIA 语义及键盘导航。
- 主界面将 WebSocket、root_seq 和 Agent Runtime 等协议词改为用户语言。
- 已新增响应式和无障碍交互的 Playwright 回归测试。

这些改动应保留，但右侧抽屉还需要完成“关闭即不可访问”的最后一步，紧凑布局也需要从悬浮覆盖改为预留空间。

## 7. 建议实施顺序

### 第一批：核心正确性

1. 建立统一事件时间线并保持主/子代理并发顺序。
2. 完成自动跟随、暂停跟随和回到最新。
3. 补齐授权信息和高风险确认。

### 第二批：最小窗口与无障碍

1. 修复 980-1100px 工具栏遮挡。
2. 修复关闭抽屉的焦点和辅助技术状态。
3. 调整主按钮颜色对比度，并增加 reduced-motion 与 live region。

### 第三批：效率与细节

1. 重组设置面板并增加删除确认。
2. 增加 Markdown、代码块和子代理详情。
3. 收敛活动面板协议标签，补齐窄屏会话导航。

## 8. 验收建议

修复完成后增加以下自动化用例：

1. 在 980px 宽度断言辅助栏与首条消息不相交。
2. 抽屉关闭时断言内部元素不可聚焦且面板不进入可访问树。
3. 混合输入乱序到达的主代理、子代理、工具和授权事件，断言按 `root_seq` 展示。
4. 长输出时断言默认跟随底部；用户上滚后不强制跳动；“回到最新”恢复跟随。
5. 高风险授权断言工具、风险、参数、目标和代理信息完整。
6. 在 520px 断言设置面板宽度等于视口宽度。
7. 对主按钮和必要文本执行自动对比度检查。

达到上述条件后，桌面端可视为满足本版 UED 规范的 v0.1 阶段验收基线。
