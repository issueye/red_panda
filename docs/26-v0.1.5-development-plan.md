# v0.1.5 Development Plan

Updated: 2026-07-09

v0.1.5 is the MCP read-only discovery slice. It should start only after v0.1.2 config CRUD and v0.1.4 Desktop config UI are complete.

## 1. Goal

v0.1.5 should add controlled MCP server startup and read-only capability discovery, stopping before provider-facing MCP tool execution.

## 2. Non-Goals

Do not include these in v0.1.5:

- MCP `tools/call`.
- Provider-facing MCP tool execution.
- Automatic long-running MCP process restart policy.
- Remote MCP transport.
- Plugin marketplace.

## 3. Deliverables

| Order | Deliverable | Scope | Done when |
| --- | --- | --- | --- |
| 1 | MCP process supervisor MVP | Gateway or dedicated MCP package | Enabled configs can start a stdio MCP server with timeout and cleanup, without exposing tools to Runtime. |
| 2 | MCP initialize handshake | Protocol/Gateway | Gateway can run `initialize` and store server metadata/errors. |
| 3 | Read-only `tools/list` discovery | Gateway API | Gateway can query tool definitions and persist or cache a redacted capability snapshot. |
| 4 | Audit and cleanup | Gateway/tests | Startup, handshake, discovery, timeout, stderr capture, and process cleanup are tested. |
| 5 | Desktop visibility | Desktop | Users can inspect discovered tools and server health without calling tools. |

## 4. Verification

Focused gate:

```powershell
go test ./modules/protocol/... ./modules/gateway/...
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\protocol-compat.ps1
cd modules\desktop\frontend
npm test
npm run test:ui
npm run build
cd ..\..\
```

Release gate should also include process-leak checks around MCP child processes.

## 5. Exit Criteria

v0.1.5 is done when:

1. MCP servers can be started for discovery and are always cleaned up.
2. `initialize` and `tools/list` results are inspectable through Gateway/Desktop.
3. MCP tools are not callable by Runtime or provider loops.
4. Failure paths for startup timeout, malformed JSON, server exit, and cleanup are covered.
