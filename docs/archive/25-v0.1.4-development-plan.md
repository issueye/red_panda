# v0.1.4 Development Plan

Updated: 2026-07-10

Status: implemented.

v0.1.4 is the Desktop MCP configuration UI slice built on the implemented v0.1.2 Gateway MCP config CRUD contract.

## 1. Goal

v0.1.4 delivers a Desktop surface for managing MCP server configuration records through the Gateway API without starting MCP processes or calling MCP tools.

## 2. Non-Goals

Do not include these in v0.1.4:

- MCP stdio process startup.
- MCP `initialize`, `tools/list`, or `tools/call`.
- Runtime tool registry changes.
- Permission evaluation for MCP tools.
- HTTP MCP transport.

## 3. Deliverables

| Order | Deliverable | Scope | Done when |
| --- | --- | --- | --- |
| 1 | Frontend MCP DTO helpers | `modules/desktop/frontend/src/lib` | MCP server config responses and payloads normalize safely, including env redaction state. |
| 2 | Settings UI integration | Desktop Settings or right-panel tool surface | Users can list, create, edit, enable/disable, and delete MCP server config records. |
| 3 | Validation feedback | Desktop UI | Gateway validation errors surface next to the relevant form without losing draft state. |
| 4 | API tests | Frontend unit/Playwright | Fixture tests cover create/edit/delete and redacted env display. |
| 5 | Status sync | Docs/README | Docs state Desktop manages MCP config only; execution remains blocked. |

All deliverables above are implemented. MCP execution remains outside this slice.

## 4. Verification

Focused gate:

```powershell
cd modules\desktop\frontend
npm test
npm run test:ui
npm run build
cd ..\..\
```

Integration gate after v0.1.2 backend exists:

```powershell
go test ./modules/gateway/... ./modules/protocol/...
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\protocol-compat.ps1
```

## 5. Exit Criteria

v0.1.4 completion boundary:

1. Desktop can manage MCP server config records through the stable Gateway API.
2. Redacted env/config data is never shown as raw secrets.
3. UI tests cover the main config workflow.
4. Docs still clearly say MCP execution is not implemented.

These criteria are met for configuration management. MCP stdio startup, initialize, `tools/list`, tool registration, permission integration, and `tools/call` remain unimplemented.
