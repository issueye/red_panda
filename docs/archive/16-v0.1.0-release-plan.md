# v0.1.0 Release Plan

Updated: 2026-07-09

This document defines the release boundary for `red_panda` v0.1.0. It is the stop line for current development: finish the listed blockers, verify the gates, update release notes, then tag/package. Anything outside this document moves to v0.2.0 or later unless explicitly promoted here.

## 1. Current Completion Snapshot

`red_panda` is functionally past MVP. The core three-layer architecture is implemented and verified:

```text
Desktop(Wails v3 + React) <-> Gateway(Gin/GORM/SQLite no-cgo) <-> Agent Runtime(stdio JSON-RPC)
```

Current completion by area:

| Area | v0.1.0 state | Completion |
| --- | --- | --- |
| Desktop | Chat, settings, provider profiles, permissions, tools, subagents, workspace panel, Activity timeline, reconnect/resume, session fork/compact, Memory panel. | Release candidate quality |
| Gateway | Gin MVC, SQLite/GORM no-cgo persistence, WebSocket routing, HTTP APIs, provider profiles, run/event/tool/permission projections, memory APIs, fork/compact APIs. | Release candidate quality |
| Agent Runtime | stdio JSON-RPC, echo/OpenAI-compatible providers, streaming provider option, tool loop, permission policy, cancellation, in-process/process/process-pool subagents, memory injection. | Release candidate quality |
| Protocol | Runtime JSON-RPC, Desktop WebSocket envelopes, `root_seq` replay/resume, permissions, tools, subagents, fork/compact, memory CRUD/preview compatibility. | Release candidate quality |
| Verification | Go tests, frontend unit tests, Playwright fixture tests, Gateway-backed E2E, protocol compatibility script, Wails build. | Strong MVP gate |

Remaining gap before v0.1.0:

- None. The full release gate passed on 2026-07-09.

Explicitly excluded from v0.1.0:

- MCP stdio implementation.
- Remote/external access hardening beyond current local WebSocket/HTTP shape.
- Vector memory search.
- Plugin marketplace or skill system.
- Broad UI redesign.

## 2. Release Definition

v0.1.0 means:

1. A local user can run the Desktop/Gateway/Runtime loop.
2. Runs are restorable, auditable, cancellable, and replayable.
3. Built-in tools use permission policy and are visible in tool/activity audit.
4. Subagents can run in-process or child-process modes, with failure/cancel visibility.
5. Provider profiles can configure OpenAI-compatible models without exposing raw API keys back to Desktop.
6. Session fork/compact and memory/history are inspectable through Desktop and Gateway APIs.
7. The final release gate passes on the local Windows development machine.

## 3. v0.1.0 Blocker Queue

Only these items block v0.1.0.

| Order | Item | Owner lane | Done when |
| --- | --- | --- | --- |
| 1 | Gateway-mediated `memory.*` Runtime tools | Protocol + Gateway + Runtime | Complete. `memory.list/create/update/delete` work through normal tool events, permission policy, and Gateway memory persistence. |
| 2 | Protocol compatibility coverage for memory tools | Protocol compatibility | Complete. External script proves create/list/denied mutation paths through public Gateway behavior. |
| 3 | Release documentation sync | Documentation | Complete. README, status, roadmap, execution plan, and release notes agree on v0.1.0 state and exclusions. |
| 4 | Build/version finalization | Release | Complete. Gateway/Agent binaries were built with `-ldflags "-X main.version=0.1.0"` and Desktop reports `0.1.0`. |
| 5 | Final release gate | Verification | Complete. All commands in section 6 passed; temporary Playwright `test-results` was removed. |

If item 1 becomes too large, it may be explicitly deferred to v0.2.0, but the release notes must say that Runtime receives memory context and Desktop can manage memory, while agent-initiated memory tools are not included.

## 4. Parallel Development Rules

Use these lanes to avoid unordered development:

| Worker | Lane | May edit | Must not edit |
| --- | --- | --- | --- |
| A | Protocol/Gateway bridge | `modules/protocol/methods`, `modules/gateway/internal/gateway/infra/runtimeclient`, focused Gateway tests | Desktop UI |
| B | Runtime tools | `modules/agent/internal/runtime`, focused Runtime tests | Gateway service/repository |
| C | Protocol compatibility | `scripts/protocol-compat.ps1` after A/B behavior exists | Runtime/Gateway core code |
| D | Release docs | `docs/*`, `README.md` after facts are verified | Code implementing active behavior |

Shared hot files require single ownership at a time:

- `modules/protocol/methods/methods.go`
- `modules/gateway/internal/gateway/infra/runtimeclient/client.go`
- `modules/agent/internal/runtime/tools.go`
- `modules/agent/internal/runtime/runtime.go`
- `scripts/protocol-compat.ps1`
- `docs/10-development-status.md`
- `docs/11-structured-development-roadmap.md`
- `docs/12-current-execution-plan.md`
- `README.md`

## 5. Execution Milestones

### RC1: Memory Tool Bridge

Scope:

- Add internal Runtime -> Gateway JSON-RPC request `memory.tool.execute`.
- Update Gateway runtime client to distinguish requests, notifications, and responses.
- Add Gateway handler that calls `MemoryService`.
- Add Runtime tool definitions and executor callback.
- Preserve existing `tool_started`, permission, `tool_finished`, and `tool_failed` behavior.

Verification:

```powershell
go test ./modules/agent/... ./modules/gateway/... ./modules/protocol/...
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\protocol-compat.ps1
```

### RC2: Release Stabilization

Scope:

- Fix only bugs found by RC1 verification.
- Update user-facing docs.
- Confirm no MCP implementation has started.
- Confirm no unexpected Gateway/Agent processes remain after Gateway-backed E2E.

Verification:

```powershell
go test ./modules/agent/... ./modules/gateway/... ./modules/protocol/... ./modules/desktop/... ./modules/cli/...
cd modules\desktop\frontend
npm test
npm run test:ui
npm run build
cd ..\..\
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\protocol-compat.ps1
cd modules\desktop
wails3 build
```

### RC3: Package Candidate

Scope:

- Build `bin\red-panda-agent.exe` and `bin\red-panda-gateway.exe` with version `0.1.0`.
- Build Desktop package.
- Write concise release notes with included/excluded features and known limitations.

Suggested binary build commands:

```powershell
$env:CGO_ENABLED='0'
go build -ldflags "-X main.version=0.1.0" -o bin\red-panda-agent.exe .\modules\agent\cmd\red-panda-agent
go build -ldflags "-X main.version=0.1.0" -o bin\red-panda-gateway.exe .\modules\gateway\cmd\red-panda-gateway
```
