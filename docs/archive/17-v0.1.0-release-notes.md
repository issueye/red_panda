# v0.1.0 Release Notes

Date: 2026-07-09

## Summary

`red_panda` v0.1.0 is the first local release candidate for the three-layer AI Agent system:

```text
Desktop(Wails v3 + React) <-> Gateway(Gin/GORM/SQLite no-cgo) <-> Agent Runtime(stdio JSON-RPC)
```

The release focuses on a restorable, auditable local agent loop with provider profiles, built-in tools, permission policy, subagents, session fork/compact, memory/history, and Gateway-mediated Runtime memory tools.

## Included

- Desktop app with chat, workspace panel, settings, provider profiles, permissions, tool cards, subagents, Activity timeline, session fork/compact controls, reconnect/resume, and Memory panel.
- Gateway service using Go + Gin + GORM + SQLite no-cgo + MVC.
- Agent Runtime subprocess using newline-delimited stdio JSON-RPC.
- Desktop/Gateway realtime communication through WebSocket only; SSE is not used.
- Built-in Runtime tools:
  - `workspace.read_file`
  - `workspace.list`
  - `workspace.grep`
  - `workspace.diff_file`
  - `workspace.write_file`
  - `workspace.edit_file`
  - `workspace.apply_patch`
  - `shell.exec`
  - `memory.list`
  - `memory.create`
  - `memory.update`
  - `memory.delete`
- Permission and tool policy flow with allowlist/denylist support.
- In-process, child-process, and process-pool subagent modes.
- Provider profiles for OpenAI-compatible providers, with masked API key state.
- Runtime memory injection and inspectable Gateway memory records.
- Runtime `memory.*` tools executed through Gateway-owned persistence via internal `memory.tool.execute` JSON-RPC.
- Session fork and compact APIs plus Desktop controls.
- Persisted run events, run/tool/permission projections, and replay/resume through `root_seq`.

## Known Limitations

- MCP stdio tools are not implemented in v0.1.0.
- Remote access hardening is not part of this release; the default target remains local use.
- Memory uses scoped records and preview selection, not vector search.
- Gateway-backed Playwright tests are serialized because they use a fixed local Gateway port and test database.

## Next

The next controlled slice should be MCP stdio tools design, not implementation. The design must define process ownership, stdout/stderr isolation, tool registry mapping, permission policy, cancellation, and tests before code starts.
